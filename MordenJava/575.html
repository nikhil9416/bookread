542 APPENDIX D Lambdas and JVM bytecode The case of a lambda expression capturing final (or effectively final) local variables or fields, as in the following example, is a bit more complex: public class Lambda { String header = "This is a "; Function<Object, String> f = obj -> header + obj.toString(); } In this case the signature of the generated method can’t be the same as the lambda expression, because it’s necessary to add extra arguments to carry the additional state of the enclosed context. The simplest solution to achieve this is to prepend the argu- ments of the lambda expression with an additional argument for each of the captured variables, so the method generated to implement the former lambda expression will be something like this: public class Lambda { String header = "This is a "; Function<Object, String> f = [dynamic invocation of lambda$1] static String lambda$1(String header, Object obj) { return obj -> header + obj.toString(); } } More information about the translation process for lambda expressions can be found here: http://cr.openjdk.java.net/~briangoetz/lambda/lambda-translation.html.
