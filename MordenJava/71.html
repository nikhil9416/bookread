Figure 2.4 summarizes our journey so far. 2.3.4 Seventh attempt: abstracting over List type There’s one more step that you can do in your journey toward abstraction. At the moment, the filterApples method works only for Apple. But you can also abstract on the List type to go beyond the problem domain you’re thinking of, as shown: public interface Predicate<T> { boolean test(T t); } public static <T> List<T> filter(List<T> list, Predicate<T> p) { List<T> result = new ArrayList<>(); for(T e: list) { if(p.test(e)) { result.add(e); } } return result; } You can now use the method filter with a List of bananas, oranges, Integers, or Strings! Here’s an example, using lambda expressions: List<Apple> redApples = filter(inventory, (Apple apple) -> RED.equals(apple.getColor())); List<Integer> evenNumbers = filter(numbers, (Integer i) -> i % 2 == 0); Figure 2.4 Behavior parameterization versus value parameterization Flexible Rigid Verbose Concise Classes Anonymous classes Behavior parameterization Lambdas Value parameterization Introduces a type parameter T
